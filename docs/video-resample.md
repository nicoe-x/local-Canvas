# 视频二次采样

选中已完成的视频，在结果工具栏点「二次采样」。填写步数、降噪强度、种子和修改要求，创建节点后再点生成。原视频保留，结果写入新节点；参数可通过输入面板的「二采参数」重新编辑。

这是把已有视频的 RGB 帧重新编码进 H3、加噪后继续采样。它和工作台现有的生成时 latent 放大二采是两条链路。画布节点使用 `settings.video_resample = {source, steps, denoise}`，其中 source 是上游视频节点 ID。只允许一个指定视频输入；断线、未完成视频、他人素材、无适配器时都会在提交前拒绝。普通输入文本仍经本地 Qwen 转换成 H3 提示词，留空时使用固定保守修复指令。

步数1–32，降噪0.05–1，默认8步、0.25。种子留空时由服务端随机生成并持久化。分辨率和帧数取自源文件，忽略二采节点的普通比例和时长控件；后者会隐藏。降噪不是线性的画面修改比例，高值可能改变身份和动作。

首版支持24fps、5–360帧、宽高32像素对齐、最短边至少256、总像素不超过1344×768的 H3 片段。音频在 H3 latent 中锁定，交付前直接复制原音轨。无音轨输入在内部填充静音用于编码，交付不新增音轨。帧数向上补到17n+5网格后严格裁回，结果尺寸、帧数、帧率和音轨存在性不一致会拒绝交付。

这不是面部一致性保证。结果状态为 `COMPLETED_UNREVIEWED`，需播放检查闪烁、五官、动作和衔接。较长、高分辨率片段的耗时与显存仍取决于设备。

## 私人适配器部署

独立开源版默认不声明此能力，不会把视频误送到通用文生工作流。要启用需提供服务端 `app.state.h3_video_resample(owner, source_job_id, options)` 队列适配器。仓库中的 `integrations/h3-private/video_resample_routes.py` 是现有私人 Studio 的实现。

从私人服务器导出最新 `gateway/{bridge,runner}.py`、`studio/{app,app_private,canvas_routes,canvas_store}.py`、`studio/static/{canvas.html,canvas-result-tools.js,canvas-result-tools.css}` 到一个源目录。运行：

```powershell
python integrations/h3-private/install_video_resample.py SNAPSHOT OUTPUT
```

脚本只输出待审查的文件，不修改运行服务。版本不匹配时失败。审查差异后备份并部署输出文件，保留原属主和权限，再重启私人 Studio。它不需要重启 ComfyUI，也不安装新节点或下载模型。依赖已有 T8 `SourceAVPrepare`、低降噪双时钟 sampler、H3 VAE 和 Ref2VA 模型。

内部任务以 `resample_of` 记录来源，所有者、输出路径、优先级由服务端确定。删除源视频前检查依赖；回收站批量彻底删除按子任务到父任务顺序执行。任务沿用现有 GPU 锁、暂停/取消和 durable render receipt；未知提交结果保持待核对，禁止盲目重发。

该 PR 依赖已有私人 H3 与脸部后处理集成，基于 `codex/h3-generation-face-pass`。不改变公共服务。

## 验证记录

2026-11-24 在私人 RTX 5090 上用2秒实片完成8步、降噪0.25的采样，耗时49.8秒。1024×576、48帧、24fps保持一致，原音轨码流哈希相同。全帧黑场/静音检测未发现新增异常。按8fps检查整个样本，并放大人脸区域：场景与步行动作保留，原片的小脸五官不稳定仍未完全解决，不能把这次功能验证当作修脸质量通过。

浏览器使用隔离画布验证入口、创建连线、参数保存/重载和再次编辑；打开弹窗和保存参数不创建生成任务。另用真实画布发起一个完整视频的二采任务，重复发送同一提交编号返回同一个任务 ID。
